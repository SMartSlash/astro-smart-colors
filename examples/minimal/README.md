# Minimal Smart Colors example

A plain HTML page consuming the generated token API. No framework, no build tool and no application JavaScript. The only authored color file is `src/styles/tokens/palette.css`, with five sources: canvas, ink, one `ui`, one `feedback` and one decorative.

The palette is the same starter palette that `smart-colors init` writes.

## Run it

Run the commands with the package installed in your project, from the example directory or with an explicit `--root`:

```sh
# 1. Generate colors.css and the smart-colors-reports/ diagnostic folder.
pnpm exec smart-colors build --automation=off

# 2. Verify the generated file is present and current (read-only).
pnpm exec smart-colors check
```

`--automation=off` means no Playwright lookup: the CSS and the diagnostic folder are still generated. Drop the flag, or use `--automation=required`, when you want browser measurement. `report` regenerates only the diagnostic folder:

```sh
pnpm exec smart-colors report --automation=off
```

If you run the example from a checkout of this package, use the local binary and the example root:

```sh
node src/cli.mjs build --root examples/minimal --automation=off
node src/cli.mjs check --root examples/minimal
node src/cli.mjs report --root examples/minimal --automation=off
# or, from inside examples/minimal:
# node ../../src/cli.mjs build --automation=off
```

If the example is copied into a consumer project, pass that project's effective root:

```sh
pnpm exec smart-colors build --root ./path/to/minimal-example --automation=off
pnpm exec smart-colors check --root ./path/to/minimal-example
pnpm exec smart-colors report --root ./path/to/minimal-example --automation=off
```

Then open `index.html` (the example page) in a browser. For diagnostics, open `smart-colors-reports/index.html` for the interactive preview and `smart-colors-reports/report.html` for the static full technical report. The folder also contains `styles/preview.css`, `styles/report.css` and `scripts/preview.js`; move or copy the whole `smart-colors-reports/` folder, not one HTML file alone. Both diagnostic documents are snapshots of the generated bytes: regenerate them after editing the palette. A legacy `reports/` directory is left untouched and is not migrated.

In a new project of your own, start with the same command `init`:

```sh
# 3. Create a palette and a colors-tuning.css panel with every value commented out.
pnpm exec smart-colors init   # or with a global install: smart-colors init
```

## What to look at

- The page background, cards and body text use `--color-bg`, `--color-surface`, `--color-text` and `--color-text-muted`.
- The button uses `--color-brand-solid` with `--color-brand-solid-text`, and hover moves to `--color-brand-solid-hover`.
- The success callout pairs `--color-success-surface` with `--color-success-text` and `--color-success-border`.
- The badge uses the decorative `--color-highlight` and its `--color-highlight-ink` companion.
- Keyboard focus (Tab) uses `--color-focus-ring`.
- Light and dark values come from generated `light-dark()` pairs and `color-scheme: light dark`; switch the OS appearance to see both.

`src/styles/tokens/colors.css` is generated, not committed here: run `build` first. Edit `palette.css`, run `build` again, and use `check` in CI. The example page itself has no script; only the generated preview folder contains the isolated local diagnostic runtime in `scripts/preview.js`.
